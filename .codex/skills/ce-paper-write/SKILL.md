# CE 논문 작성

논문 작성자는 안정화된 원장의 주장과 지위를 읽어 독자가 따라갈 수 있는 논증으로 바꾼다. 원장의 지위를 새로 판정하거나 수정하지 않는다.

## 공통 규약

작업 전에 `../ce-doc-write/SKILL.md`의 형식적 출처, 논문형 문서, 처음 읽는 독자 게이트, 문체와 수식 표기, 번역투 방지를 읽고 적용한다.

연구 run에서 나온 논문·유도라면 `../../harnesses/ce_research_docs_policy.md`도 읽는다. `_workspace`의 final report는 증거 요약일 뿐 정본 원고가 아니며, 독자용 결과는 저장소 루트의 기존 `docs` 문서에 반영한다. 외부 복제본이나 하위 저장소의 `docs`는 루트 정본을 대신하지 못한다.

사용자가 다른 언어를 분명히 요구하지 않았다면 정본 본문은 한국어로 쓴다. 수식
기호, 코드·명령 식별자, 원문 서지명과 첫 등장 전문용어만 영어를 허용한다. 영어
레인 문장을 번역 없이 정본에 옮기지 않으며, 계산의 전제와 논리 연결을 한국어
논문체로 다시 쓴다.

## 소유 경계

- 강의, 유도, 논문 원고, 독자 가이드만 편집한다.
- 저장소 루트의 기존 정본 경로를 우선한다. 이론 유도와 물리 논문형 원고는 루트 `docs/5_유도`, 강의는 루트 `docs/1_강의`, 별도 publication tree는 루트 `docs/` 아래에 이미 있을 때만 그 경로를 쓴다.
- 같은 주제를 자세히 다시 쓰는 요청은 새 `_workspace`나 중복 원고를 만들 이유가 아니다. 기존 정본을 확장한다.
- 원장은 수정하지 않는다.
- 원장과 원고를 함께 다루면 안정화된 원장을 읽기 전용 입력으로 사용한다.
- 원장의 지위·기호·수치가 논문에 맞지 않아 보여도 직접 고치지 않는다. 충돌 위치와 필요한 원장 수정을 보고한다.
- 같은 작업자가 원장과 원고를 오가며 동시에 편집하지 않는다.

## 개요 게이트

초안 요청에는 본문보다 먼저 아래 개요를 제시하고 확인받는다.

1. 핵심 기여를 한두 문장으로 고정한다.
2. 전제 독자를 "이 주제를 1년 전에 처음 배우던 저자"로 적는다.
3. 문서 유형을 독립 논문, 강의, 유도, 독자 가이드 중 하나로 정한다.
4. 정의 → 보조정리 → 핵심 정리 → 따름정리의 의존 관계를 적는다.
5. 각 절의 목적과 앞 절에서 넘겨받는 결과를 한 문장씩 적는다.
6. 공리, 외부 입력, 근사, 경계조건, 미완성 다리를 본문보다 먼저 목록화한다.

## 구조

독립 수학 논문은 제목 → 초록 → 서론 → 본론 → 남은 문제 → 참고문헌 순으로 쓴다. 별도 결론 절은 두지 않는다. 서론 앞부분에 핵심 결과를 제시하고 표준 정의는 필요한 자리로 미룬다.

강의·유도·독자 가이드는 독립 논문의 절 이름을 억지로 복제하지 않는다. 대신 첫 두 문단에서 무엇을 보이는지, 왜 필요한지, 어떤 순서로 진행하는지 밝히고 각 절을 목적 문장으로 시작한다.

## 논증과 문장

- 뇌/AGI 논문형 문서는 `.codex/harnesses/real_brain_equation_discovery_loop.md`에 따라 확립된 생물 기전식·측정모형과 저자의 CE 추가항 경계를 먼저 밝히고, 사전 고정 실데이터 시험, 실패·잔차, 대안 모델과 판본 개정을 숨기지 않는다. simulator 성과는 L0로 분리하며 생물학적 결론을 대체하지 않는다.
- 정의를 사용하는 정리보다 앞에 둔다. 정리, 보조정리, 따름정리를 구분한다.
- 본문 증명은 "증명."으로 시작해 `□`로 끝낸다. 정본 증명 원장을 링크하는 문서는 링크의 범위와 필요한 전제를 한 문장으로 요약한다.
- 유도는 한 줄에 한 단계씩 쓰고 적용한 정의·가정·법칙을 말로 밝힌다. 조건, 근사와 경계조건을 생략하지 않는다.
- 직관은 "직관적으로는" 또는 "참고(Remark)"로 표시하고 증명과 섞지 않는다.
- 지위 태그를 문단의 표지로만 쓰고 태그 블록을 연속 나열하지 않는다. 태그 사이에는 앞 결과와 다음 목적을 잇는 산문을 둔다.
- 저자의 독자적 제안은 "본 논문에서 제안하는"이라고 밝힌다. 논증 공백은 문장으로 메우지 않고 원장 작성자에게 돌려보낸다.
- 문장을 기호나 숫자로 시작하지 않고, 산문의 논리 기호는 말로 푼다. 한 문단에는 한 아이디어만 둔다.

## 상세성 게이트

논문·유도는 독자가 run 파일이나 원장을 따로 열지 않아도 재현할 수 있게 쓴다.

- 동기와 목표, 정의·타입·차원, 공리·외부 입력·경계조건을 먼저 밝힌다.
- 핵심 식은 정의에서 방정식과 관측량까지 한 단계씩 유도하고, 각 등호에 쓴 가정이나 법칙을 말로 적는다.
- 반례가 있으면 실패한 식과 정확한 실패 줄을 보이고, 수정식이 그 문제를 어떻게 해소하는지 다시 계산한다.
- 보존식, 중복계상, 안정성 domain, 전역 조건, 수치 normalization과 관측 baseline을 생략하지 않는다.
- 마지막에는 정리·공리·경험식·미완성 bridge의 지위, 다음 falsifier와 재현 경로를 분리한다.

분량을 늘리기 위한 반복은 피하되, 중간 계산과 논증 연결을 생략한 짧은 요약은 완성 원고로 보고하지 않는다.

## 탈고 게이트

처음 읽는 독자의 눈으로 처음부터 다시 읽고 기호의 첫 등장, 정의 사용 순서, 절 사이 연결, 종이와 펜 재현 가능성, 번역투를 검사한다. 원장 표처럼 읽히는 강의·유도 원고는 완성으로 보고하지 않는다.
