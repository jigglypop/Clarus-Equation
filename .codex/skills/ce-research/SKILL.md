# CE Research

> 현재 저장 정책: run 파이프라인(`CE_RUN`, stage 파일)은 은퇴했다. `paper/`에는 결과만 쓰고, 시행착오·중간 계산·아이디어 주차장은 `_workspace/<YYYYMMDD>-<트랙>-<주제>.md` 노트 하나에 둔다(상한은 `_workspace/README.md`, `python.cmd harness`가 강제). 세션의 현황판이자 유일한 표적은 `paper/진전_원장.md` §2다. 매몰 방지 규칙은 `../../harnesses/goal_pursuit.md`.

역할 카드는 해당 레인을 실행하는 순간에만 읽는다. 모든 카드를 선로딩하지 않는다.

## 실행 계약

- 목표, 정의역, 주장, 허용 오차, falsifier와 완료 조건은 현재 작업 계획에 고정한다. 사용자가 사전등록·audit bundle·release evidence를 명시하지 않았다면 별도 연구 번들을 만들지 않는다.
- 시작할 때 `paper/진전_원장.md` §2(현재 표적)·§5(열린 다리)·§6(트랙 현황)을 읽고, 이번 작업이 어느 고리를 닫는지 한 줄로 고정한다. 그 뒤 `paper/README.md`와 대상 분야의 읽기 지도를 거쳐 기존 주장·기호·판본·열린 의무를 확인한다. 이미 닫힌 결과를 재유도하지 않는다.
- 세션을 열면 `_workspace/`에 주제 노트 하나를 만들거나 이어 쓴다(템플릿은 README). 시도 로그·주차장·흡수 판정 세 표만 쓰고, 산문·유도 전문·로그 덤프는 넣지 않는다. 흡수가 끝나면 노트를 삭제한다.
- 작업 중 떠오른 아이디어는 주차장에 한 줄로 적고 현재 단계가 끝나기 전에는 실행하지 않는다. 우회 탐색은 세션당 1회, 툴 호출 15개 이내. 툴 호출 10개마다 `[정렬]`/`[이탈]` 한 줄을 남기고 `[이탈]` 연속 2회면 표적 단계로 복귀한다.
- 임시 계산은 OS 임시 디렉터리에서 수행하고, 재현 가치가 있는 결과만 코드·테스트·원장에 옮긴다.

`.codex` 하네스·스킬·역할 카드의 문구, 실행 범위 또는 cache 정책을 고치는 요청은 이 연구 파이프라인의 대상이 아니다. 이 경우 run과 레인을 만들지 말고 대상 설정 파일만 spot 수정한다.

## 목표 정렬 게이트

연구 계획에는 `$ce-explanation-planner`의 목표 계약을 적용한다. 시작할 때
최종 목표·현재 하위 목표·완료 조건·고정 제약을 사용자에게 설명하고, 다음
네 시점마다 현재 작업이 어느 미완성 고리를 닫는지 다시 확인한다.

- 새 source/math 레인을 열기 전
- 감사에서 구현으로 넘어가기 전
- 반례 때문에 증명 순서나 기전을 바꿀 때
- 상태 요약·인계·정본 반영 전

각 점검은 `[정렬]`/`[이탈]`/`[범위변경]`과 근거를 남긴다. 목표 이탈이면
원인과 **복귀 행동**을 계획에 넣고 정렬을 회복한 뒤 진행한다. 사용자 지시로
범위가 바뀐 경우에는 새 완료 조건을 명시한다. 테스트·문서량 증가만으로는 목표
진척으로 세지 않으며, 어떤 주장 고리와 falsifier를 닫았는지 연결해야 한다.

정본은 `../../harnesses/closure_budget.md`다. 요지는 다음과 같다.

- 세션의 진전은 **예측**(추측 카드 채택: 사전등록 숫자·극한 복원·kill·사다리),
  **닫힘**(고리 하나 `[정리]`/`[산출]` 확정), **기각**(완전 반례·no-go와 재개 조건),
  **축소**(좁은 정리 분리) 넷뿐이다. 새 장·새 원장
  항목·하위 게이트 분할·테스트 수 증가는 "개시·정리"로 기록한다.
- 새 원장 항목이나 새 장은 진전 원장 §2의 표적과 어느 고리로 연결되는지 한
  줄을 머리에 적어야 연다. 한 항목의 하위 게이트가 셋을 넘으면 표적 재정의·
  경로 기각·공리 명시 추가 중 하나를 §2에 기록한 뒤에만 계속한다.

## 산출물 위생

- 같은 결론의 초안·v2·final 사본을 만들지 않고 기존 `paper/` 정본을 제자리 갱신한다.
- 수식은 블록 `$$ ... $$`(별도 줄), 인라인 `$...$`만 쓴다. 수학 기호는 코드스팬이 아니라 수식 모드로 쓴다.
- 영어 용어는 첫 등장에 "한국어(영어)"로 병기하고 이후 한국어만 쓴다. 새 용어는 해당 폴더 용어사전(`paper/6_최신_연구/용어사전.md`, `paper/9_등호이전/09_용어사전.md`)에 등록한다.
- 구현 검증은 `$ce-validate`의 최소 범위 규율을 따른다. 연구 요청이라는 이유만으로 전체 pytest·전체 bench를 실행하지 않는다.

## 연구 흐름

1. **질문 고정**: 진전 원장 §2와 대조해 목표 계약을 설명하고 질문·정의역·주장·기호·허용 오차·선행 결과·완료 조건·kill 조건을 확인한다.
1-1. **식 고정(추측 우선)**: 보조정리보다 먼저 예측식 또는 예산식을 한 줄로 세운다. 유도 없이 `[공리: 후보]`로 선언하되 숫자(또는 장부 항등식)·기존 극한 복원·kill 2개 이상·증명 사다리(≤7단)를 결과를 보기 전에 적고, physics source 레인으로 신규성을 확인한다. 문헌과 identical·special_case면 그 식은 버리고 더 강한 식을 세운다. 이후 단계는 사다리 한 단씩만 닫는다.
2. **조건부 레인**: 최신 외부 근거가 필요할 때만 physics source 레인, 유도·반례·대안 경로에는 math 레인을 쓴다. 레인 산출은 서로의 결론을 미리 주입하지 않는다.
3. **안정 스냅샷 감사**: source와 math 레인이 끝난 뒤 auditor가 같은 스냅샷에서 출처 역할, 논리 의존, 수치 오차와 미완성 bridge를 분리한다. Gate 어휘는 PASS·REVISE·PIVOT·BLOCKED다.
4. **구현**: 감사로 승인된 최소 범위만 한 implementation owner가 구현하고 `$ce-validate`로 검증한다.
5. **반례·대안 경로**: 완전한 반례는 부모 주장과 witness를 잠그고, 실패 가정이 서로 다른 기전 경로를 판별 예측·음성대조·중단 조건으로 비교한다.
6. **정본 반영**: 원장을 먼저 갱신한 뒤 논문 작성자가 그 원장을 읽기 전용 근거로 사용한다.
7. **세션 종료**: 진전 원장 §2(표적·완료 조건·kill 조건·갱신일)와 §7(세션 로그 한 행)을 갱신하고 `.codex/hooks/python.cmd links`를 실행한다.

## 원장과 집필 소유권

- 주장·상수·판본·진리값은 `$ce-ledger-write`가 먼저 안정화한다.
- 강의·유도·독자 가이드·논문은 `$ce-paper-write`가 원장을 읽기 전용 입력으로 사용한다.
- 어떤 판정도 강화하지 않는다. 새 증거가 필요하면 문장으로 메우지 말고 해당 source·math 레인으로 돌려보낸다.

## 끈질김 (진취성 규율)

- **BLOCKED는 최후 수단이다.** 주장이 막히면 먼저 반례를 잠그고, 실패한 가정을 서로 다르게 바꾸는 기전 route를 최소 3개 구성해 판별 실험을 시도한다. 구조적으로 가능한 route가 없다는 no-go 또는 세 route의 kill condition 충족을 기록한 뒤에만 BLOCKED를 쓴다.
- BLOCKED에는 **재개 조건**(무엇이 오면 다시 열리는지)을 반드시 적는다. 재개 조건 없는 BLOCKED는 미완성 감사다.
- ABANDONED는 구조적 불가능(반례 확정, no-go, 필요한 증거의 원천 부재)의 근거가 있을 때만 쓴다. 분량·피로·세션 길이는 사유가 아니다.
- **재발견은 축소가 아니라 확장 신호다.** 유도가 문헌의 특수 사례로 판명되면 좁히지 않는다. 그 결과를 극한으로 포함하되 문헌이 말하지 않는 숫자 하나를 더 내는 식(추측 카드)을 세우고, 문헌과 갈라지는 판별 사례를 kill에 넣는다. 안전한 추측(자명하게 참, 정의의 재서술)은 재발견과 같다.
- 부정 결과도 완결한다: 반례·기각은 실패한 식의 음성대조군이자 다음 pivot의 입력이다. 부모 주장은 철회하되 연구 목표는 모델 클래스 전체의 no-go가 나오기 전까지 자동 축소하지 않는다. 기각도 진전 원장 §4에 행으로 남긴다.
- 작업을 끝낼 때는 현재 결론, 부정 결과, 남은 의무와 재개 조건을 정본과 인계에 함께 남긴다. 자동 stop 훅이 상태를 대신 판정한다고 가정하지 않는다.

닫힘 판단에는 `$ce-closure-gate`, 무차원 식에는 `$ce-dimensionless`, 원장에는 `$ce-ledger-write`, 논문과 강의에는 `$ce-paper-write`를 적용한다.

마지막 상태 메시지에는 진전 종류(닫힘·기각·축소·개시·정리), 바뀐 정본·코드·테스트 경로, 실제 검증 명령과 결과, 남은 미완성 bridge와 다음 falsifier를 구분해 남긴다. 사용자가 발행을 지시한 경우에만 main agent가 Git 상태를 바꾼다.
