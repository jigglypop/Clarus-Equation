# CE 연구 정본 집필·workspace 억제 하네스

이 하네스는 CE 연구에서 `_workspace/ce`를 증거 보관소로만 사용하고, 독자가
읽는 논문·유도·강의는 기존 `docs` 정본에 자세히 남기기 위한 admission gate다.
일반 코드 수정이나 단순 문서 교정에는 연구 run을 열지 않는다.

## 정본 루트 고정

이 저장소의 사용자용 정본은 항상 저장소 루트의 `docs/`다. 현재 작업공간에서는
`C:\Users\dongh\OneDrive\Desktop\Clarus-Equation\docs`를 뜻한다.

- 연구 결과, 반례 뒤 수정식, 자세한 유도와 논문 개정은 먼저 루트 `docs/`의
  기존 문서에 반영한다.
- `_workspace/ce`의 stage·artifact·최종 보고서는 증거 보관소일 뿐 정본이 아니다.
- `C:\dev` 등 외부 복제본, 하위 저장소 또는 별도 작업공간의 `docs`를 갱신해도
  루트 `docs/` 갱신을 대신하지 못한다.
- 같은 주제의 기존 루트 문서를 제자리에서 고친다. 날짜·반례·상세화만으로 새
  문서, 새 논문 사본 또는 새 workspace를 만들지 않는다.
- 완료 보고의 `CE_DOC`는 반드시 루트 기준 상대경로 `docs/...`를 가리킨다.

## 0. 집필 언어 고정

사용자가 다른 언어를 명시하지 않는 한 `docs`의 강의·유도·논문 원고와 연구
보고의 본문은 한국어로 쓴다. 영어는 수식 기호, 코드·명령 식별자, 논문 원제와
처음 한 번 병기하는 전문용어에만 쓴다. 영어 레인 산출물을 정본에 그대로 붙이거나
영어 절을 새로 만드는 것은 완료로 인정하지 않는다. 레인의 계산을 인용하더라도
정본에서는 논리와 유도를 한국어 문단으로 다시 작성한다.

## 1. 새 run admission gate

`run init`보다 먼저 다음을 확인한다.

1. 같은 주제의 active run, 미완성 run, 직접 predecessor와 기존 정본 문서를 찾는다.
2. 같은 부모 주장에 대한 반례 수정, 식 재유도, 수치 재검산, 설명 보강,
   논문 개정이면 새 run을 만들지 않고 기존 run과 기존 `docs` 문서를 이어 쓴다.
3. active 또는 미완성인 같은 주제 run이 하나라도 있으면 그것을 닫기 전에는 새
   run을 만들지 않는다. 주제별 active run은 최대 하나다.
4. 새 run은 새로운 falsifiable 부모 주장, 독립 mechanism, 독립 dataset/protocol
   또는 별도 release contract가 실제로 필요하고, 기존 run에 합치면 provenance가
   깨질 때만 허용한다.
5. 새 run을 허용할 때에도 먼저 최종 정본 경로를 선언한다. 정본 경로가 없다는
   이유로 사용자용 논문을 `_workspace`에만 쓰지 않는다.

`init`의 `REUSE?`는 제안이 아니라 같은 주제에서는 재사용 명령이다. 날짜가
바뀌었다는 이유, 설명을 더 자세히 쓴다는 이유, 반례 뒤 식을 고쳤다는 이유만으로
run-id를 늘리지 않는다.

## 2. 산출물 위치

`_workspace/ce/<run-id>`에는 계약, source/math lane, 감사, 구현·검증 기록,
재현 artifact와 `40-final-report.md`만 둔다. 이 파일들은 provenance와 심사
증거이며 사용자용 정본 논문을 대신하지 않는다.

독자가 읽는 결과는 저장소 루트의 기존 `docs` tree에 반영한다.

- 주장·상수·판본·진리값: `docs/검증_원장`의 기존 원장
- 이론 논문형 유도·새 식의 단계별 전개: `docs/5_유도`의 기존 주제 문서
- 강의와 입문 설명: `docs/1_강의`의 기존 주제 문서
- 저장소에 별도 publication 경로가 이미 있으면 그 기존 경로

별도 publication 경로도 루트 `docs/` 아래에 있을 때만 이 저장소의 정본으로
인정한다.

항상 기존 정본을 우선 개정한다. 같은 내용을 새 파일과 새 run에 반복 복제하지
않는다. 새 문서가 정말 필요하면 기존 목차와 링크 관계를 확인한 뒤 `docs` 안에
한 번만 만든다.

## 3. 자세한 논문·유도 게이트

원장이 안정된 뒤 `ce-paper-writer`와 `$ce-paper-write`가 원장을 읽기 전용으로
사용해 정본을 작성한다. 정본은 최소한 다음 논증을 처음 읽는 독자가 다른 run
파일을 열지 않고도 따라갈 수 있어야 한다.

1. 무엇을 설명하거나 증명하는지와 왜 필요한지
2. 대상의 타입, 정의역, 기호, 차원과 기준 scale
3. 채택 공리, 외부 입력, 초기·경계조건과 근사
4. 정의에서 장방정식과 관측량까지 한 단계씩 이어지는 유도
5. 발견된 반례의 정확한 식과 실패한 줄
6. 반례 뒤 바꾼 식·경계조건 및 그 수정이 문제를 해소하는 계산
7. 보존식, 중복계상 금지, 안정성·적용 domain과 전역 조건
8. 재현 가능한 수치 조건, 비교 baseline, 관측 판정과 parameter accounting
9. 증명된 정리, 채택 공리, 경험식, 미완성 bridge의 명확한 claim ceiling
10. 다음 falsifier와 재현 경로

태그 목록, 결과표, `40-final-report.md` 링크만 나열한 문서는 논문 완성이 아니다.
핵심 식은 중간 단계를 생략하지 않고 각 단계에 사용한 정의·가정·법칙을 산문으로
밝힌다. “자세히”는 반복 문장을 늘리는 것이 아니라 독자가 종이와 펜으로 재현할
수 있게 논증의 빈칸을 없애는 뜻이다.

## 4. 완료 조건

사용자가 논문, 유도, 자세한 설명 또는 정본 반영을 요청했다면 다음이 모두 끝나야
완료다.

- 같은 주제의 기존 run을 재사용하거나, 새 run admission 근거를 기록했다.
- 원장을 먼저 안정화했다.
- 관련 `docs` 정본을 자세한 독자형 문서로 갱신했다.
- 갱신 경로가 저장소 루트의 `docs/` 아래임을 확인했다.
- 반례와 폐기된 식을 숨기지 않고 새 식과 구분했다.
- 정본 경로, 검증 명령, hash 또는 변경 manifest를 보고했다.

정본 갱신이 빠진 채 `_workspace` 보고서만 완성한 상태는 연구 완료가 아니다.

## 5. 반례 뒤 연구 연속성

후보 식에 반례가 생기면 `.codex/harnesses/ce_counterexample_pivot_loop.md`를
적용한다. 실패한 식은 음성대조군으로 고정하고, 연구 목표를 유지한 채 같은 run의
구조적 route로 전환한다. 한 식의 실패만으로 부모 목표를 축소하거나 새 날짜의
workspace를 만들지 않는다.

## 6. live workspace 수명주기

`_workspace/ce`의 최상위에는 다음만 남긴다.

- 현재 이어서 쓰는 연구 envelope
- 아직 닫히지 않은 run
- 정본·하네스가 직접 참조하거나 `.pin`에 보존 이유를 적은 run

완결되고 참조되지 않은 run은 reference-aware `run.cmd gc _workspace/ce`로
`_archive/`에 이동한다. `REFERENCED`, `PINNED`, `COLLISION`으로 보고된 run은
자동 이동하지 않으며 참조 경로를 몰래 다시 쓰지 않는다. `_archive`의 과학 증거는
용량이 크다는 이유만으로 자동 삭제하지 않는다.

컴파일 target, `__pycache__`처럼 원본과 명령으로 재생성 가능한 정확한 cache만
별도로 삭제할 수 있다. 삭제 전 실제 경로가 `_workspace/ce` 아래인지 확인하고,
사용자 데이터·stage 문서·artifact를 cache로 추정해 지우지 않는다.
