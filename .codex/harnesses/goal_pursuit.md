# 목표 추적 하네스 (매몰 방지)

Status: `ACTIVE / POLICY` (2026-09-02 제정)

이 계약은 작업 도중 떠오른 해결 아이디어에 매몰되어 표적에서 멀어지는
것을 막는다. 표적은 `paper/진전_원장.md` §2 하나뿐이고, 세션의 모든
단계는 그 표적의 어느 고리를 닫는지로만 정당화된다. 닫힘 예산
(`closure_budget.md`)이 "무엇이 진전인가"를 정하고, 이 계약은 "어떻게
표적을 놓치지 않는가"를 정한다.

## 1. 표적 주입

- Claude는 `UserPromptSubmit` 훅으로 매 프롬프트마다 진전 원장 §2의 표적·
  완료 조건·kill 조건을 문맥에 주입한다(`hooks/goal_reminder.py`). Codex는
  세션 시작 시 같은 스크립트 출력을 읽는다.
- 세션 첫 메시지에서 오케스트레이터는 "이번 세션이 닫을 고리"를 한 문장으로
  적는다. 표적과 연결되지 않는 요청은 `[범위변경]`으로 표시하고 사용자에게
  묻는다. 사용자가 범위를 바꾸면 그것이 새 표적이다.
- 최종 목표는 진전 원장 §2의 `최종 목표` 행과 `paper/연구_목표_계약.md`를
  따른다. 2026-09-05 사용자 갱신의 접힘 에너지 경로 보존, 0D 에너지 보충과
  암흑에너지·암흑물질, 일반상대론·중력과 전자기·약력·강력 통합을 모두 상기한다.
  기존 허블 텐션 검증도 유지하며 중력의 조건부 유도만으로 완료 처리하지 않는다.

## 2. 아이디어 주차장

- 작업 중 떠오른 해결 아이디어·우회 경로·새 후보는 **실행하지 않고** 현재
  `_workspace/` 노트의 "주차장" 표에 한 줄로 적는다: 아이디어, 표적 연결
  여부(연결/무관), 예상 비용(툴 호출 수), 죽이는 시험 한 줄.
- 연결된 아이디어는 현재 단계가 끝난 뒤 큐 순서대로 하나씩 꺼낸다. 무관한
  아이디어는 세션 안에서 실행하지 않는다.
- 우회 탐색 예산은 세션당 1회, 툴 호출 15개 이내다. 초과하면 결과와 상관없이
  주차장에 결과 한 줄을 적고 표적 단계로 돌아온다.

## 3. 정렬 체크포인트

- 단계 전환마다 최종 목표와 현재 고리의 연결을 먼저 한 문장으로 적고,
  필요한 공리·예측식·그 식을 죽이는 시험·다음 증명 고리를 제시한다.
  공리는 물리적 선택과 증명할 주장을 구분하고, 예측식에는 정의역·단위·고정
  매개변수·표준 극한·판정 기준을 붙인다. 새 물리 후보에는 `closure_budget.md`의
  추측 카드 규칙을 적용하고, 이미 본 결과의 재현을 사전 예측으로 바꾸지 않는다.
- 유망한 기전의 공리·예측식을 적극적으로 구성하되, 독립된 반증 가능성이 있는
  후보들을 비교해 다음 하나를 선택한다. 자료마다 다른 보정항을 추가하거나
  후보 수·문서량만 늘리는 것을 최종 목표의 진전으로 세지 않는다.
- 사용자 지시에 따라 공리 후보를 생성·수정할 수 있다. 반례와 판본을 보존하며
  약식 계산·극한·차원·간단한 반례로 선별한 뒤 생존 후보를 독립 유도·전체 보존·
  수치 수렴·공동 관측으로 강하게 검증한다. 약식 통과를 증명이나 관측 성공으로 세지 않는다.
- 툴 호출 10개마다, 그리고 파일을 편집하기 직전마다 한 줄 정렬 감사를
  남긴다: `[정렬] <현재 단계> → <표적 고리>` 또는 `[이탈] <원인> → <복귀 행동>`.
- `[이탈]`이 연속 2회면 현재 작업을 즉시 멈추고 표적 단계로 복귀한다. 진행
  중이던 계산·초안은 주차장에 경로만 남긴다.
- 반례가 나오면 반례를 잠그고 표적을 유지한다. 문헌 재발견이 나오면 좁히지
  않고 표적을 유지한 채 더 강한 식(추측 카드)으로 확장한다. 표적 변경은 사용자의
  `[범위변경]`으로만 일어난다. 하위 게이트를 넷째로 여는 대신 닫힘 예산
  §2의 세 선택(표적 재정의·기각·공리 추가)을 §2에 기록한다.

## 4. 역할별 적용

- math-verifier의 routes 후보는 주차장 후보다. 오케스트레이터 판정 없이
  후보를 구현·확장하지 않는다.
- impl-engineer는 감사로 승인된 범위 밖의 코드를 "겸사겸사" 고치지 않는다.
- paper-writer는 표적 고리와 연결된 장만 고친다. 다른 장의 개선점은
  주차장에 적는다.

## 5. 세션 종료 보고

세션 마지막 메시지는 다음 순서를 지킨다. (1) 표적 대비 진전 종류(닫힘·
기각·축소·개시·정리), (2) 주차장에 남긴 아이디어 수와 그중 연결된 것,
(3) 갱신한 정본 경로, (4) 실행한 검증, (5) 다음 세션의 첫 단계 한 줄.
"흥미로운 발견"은 (2)에만 들어간다.

## 6. 기계 검사 범위

`goal_reminder.py`는 표적을 출력할 뿐 정렬을 판정하지 않는다. `harness`는
이 파일과 스크립트의 존재만 검사한다. 정렬 감사의 정직성은 세션 보고에 대한
사람의 검토가 맡는다.
