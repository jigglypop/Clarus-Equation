# 실측 교정 루프 하네스

Status: `ACTIVE / POLICY`

Date: 2026-08-22

수치 실험, backend parity, 이론 대 관측 비교에서 불일치가 났을 때 무작정
재실행하거나 허용오차를 늘리는 대신, **왜 이런가를 먼저 분류하고 허용된
대상만 교정하는** 표준 루프를 정의한다. 모든 CE 수치 하네스
(`curvature_backend_parity.md` 포함)와 이론 검증 run이 이 루프를 공유한다.

## 1. 진입 조건

다음 중 하나가 관측되면 루프에 진입한다. 진입 전 같은 명령의 단순 재실행은
1회까지만 허용한다(비결정성 배제 목적, 그 이상은 금지).

- backend parity 상태가 `BACKEND_PARITY_FAIL`
- 이론 예측 대 기준선 잔차 $|z|>3$ (§5)
- 무차원성·차원 검사 불일치
- 성능 회귀가 직전 기록 대비 2배 이상 (P2 전용 트랙, §7)

## 2. 두 개의 레지스터

**교정 가능** (루프의 조치 대상):

- 구현 코드 (Python oracle, Rust kernel, CUDA kernel, binding)
- run 계약(00-contract) 또는 하네스 문서에 **결과를 보기 전에** 선언된
  자유 파라미터
- 관측 기준선 값 — 단, ce-physics-sourcer가 출처·최신성을 검증한 갱신만.
  갱신 전후 값과 출처를 모두 기록한다

**교정 불가** (결과를 본 뒤에는 절대 바꾸지 않는다):

- tolerance, fixture, rank/condition cutoff, acceptance matrix
- endpoint·threshold·seed (바꾼 재시도는 같은 경로의 퇴역 사유다)
- 형식 지위 — 기계 상태 문자열로 이론 지위를 덮지 않는다

교정 불가 항목을 바꿔야만 통과한다면 그것은 교정이 아니라 **새 계약**이며,
사유를 적고 새 fixture 동결부터 다시 시작한다.

## 3. 루프 프로토콜

사이클당 가설 1건, 조치 1건, 최소 재검 1건. 불일치 하나당 3사이클 상한.

1. **최소 재현** — 불일치를 보이는 가장 작은 fixture 하나로 줄인다.
2. **첫 분기점 식별** — 직렬화된 중간값을 앞에서부터 비교해 처음 어긋나는
   연산을 찾는다. 최종값만 보고 추측하지 않는다.
3. **원인 분류** — §4의 분류표를 D→I→P→C→B→T 순서로 적용한다 (값싼 원인,
   흔한 원인 먼저). 분류 근거는 재현 가능한 수치 시그니처여야 한다.
4. **교정 1건** — 분류된 클래스의 허용 조치만, 한 번에 하나만 적용한다.
5. **최소 재검** — 1의 fixture만 다시 실행한다. green이면 원래 실패한
   검사 수준까지만 확대한다. 전체 재검은 하지 않는다.
6. **기록** — §6 형식으로 사이클을 기록하고 종료 조건(§7)을 판정한다.

## 4. 원인 분류표

| 클래스 | 수치 시그니처 | 허용 조치 |
|---|---|---|
| **D** 차원·단위 | 잔차가 상수배 — $10^n$, $2\pi$, $c/\hbar/k_B$ 조합비 | $ce-dimensionless 재검, 기준 스케일 정규화 수정 |
| **I** 구현 | 특정 중간 연산에서 oracle과 첫 분기 | 해당 backend 코드 수정 (impl-engineer) |
| **P** 정밀도 | f32↔f64 차이, 상쇄, 큰 condition number | f64 강제, inverse 대신 solve. tolerance 완화 금지 |
| **C** convention | 부호·기저·순서 재배열로 일치 | convention 고정 지점을 계약에 명시하고 한쪽으로 통일 |
| **B** 기준선 | 예측은 안정, 인용 관측값이 구식·오차 재산정 | sourcer 검증 후 기준선 갱신, 전후 값·출처 기록 |
| **T** 이론 | D–B 전부 기각 후에도 잔차 유지 | 코드로 흡수 금지. P0/P1 판정 후 $ce-closure-gate 회부 |

T 분류는 앞 5개 클래스의 기각 근거가 각각 기록된 뒤에만 쓸 수 있다.
반대로, 실제 이론 결함을 D–C 조치로 가려서 green을 만드는 것은 정직성
규율 위반이다.

## 5. 실측 기반 추론 규약

이론 검증의 모든 수치 비교는 아래 4열을 artifacts에 남긴다. "가깝다"는
서술은 잔차 없이 쓰지 않는다.

| 예측값 | 기준선 값 (출처·판) | 오차 $\sigma$ | 잔차 $z=(\text{pred}-\text{obs})/\sigma$ |

해석 규약:

- $|z|\le1$ — 관측 일치. **증명이 아니다** (관측 근접 ≠ 유도).
- $1<|z|\le3$ — tension. P2로 목록화, 결론이 이 값에 의존하면 P1.
- $|z|>3$ — P0 후보. 이 루프에 진입하며, T 분류가 확정되면 P0.

이론 오차와 관측 오차가 둘 다 있으면 합성 $\sigma$를 쓰고 합성 방식을
기록한다. $\sigma$가 없는 비교는 잔차 대신 상대 편차를 쓰되 판정 어휘
($|z|$ 등급)를 쓰지 않는다.

## 6. 기록 형식

run 안이면 `artifacts/calibration-log.md`, run 밖 spot 작업이면 해당
하네스 문서 옆에 기록한다. stage 파일에는 최종 판정과 경로만 남긴다.

| 사이클 | 관측 (첫 분기점·잔차) | 분류 | 가설 | 조치 | 재검 결과 | 판정 |
|---|---|---|---|---|---|---|

각 행의 조치는 diff 또는 커밋 해시로 추적 가능해야 한다.

## 7. 종료 조건

- **수렴** — 원래 실패한 검사가 교정 불가 레지스터를 건드리지 않고 green.
  루프 종료, 로그에 최종 분류 기록.
- **T 확정** — 이론 잔차로 판정. P0/P1 승격, closure-gate 회부. 루프는
  성공적으로 종료된 것이다 (죽은 경로 확인은 산출이다).
- **3사이클 소진** — BLOCKED로 기록하되 재개 조건(어떤 정보·능력이 오면
  다음 사이클이 가능한지)을 필수로 남긴다. 소진은 포기 사유가 아니다.

성능 회귀 트랙은 예외적으로 가볍게 돈다: 원인(빌드 플래그, device, batch
크기, sync 패턴)을 1사이클 안에 분류해 P2로 기록하고, 과학 판정과 절대
섞지 않는다. 속도는 수학적 통과를 대신하지 않는다.

## 8. 식 개정 프로토콜 (T 확정 이후)

T(이론) 분류가 확정된 잔차만이 식 개정의 근거다. 개정은 계약 수준
행위이며 다음을 전부 만족해야 한다.

1. **판본 보존** — 구 판본을 반례·기각 근거·적용 범위와 함께 원장에
   남긴다. 반례가 완전하면 부모 주장은 활성 문서에서 제거하되 witness는
   코드에 유지한다 (`ce-closure-gate` 규약).
2. **같은 run의 새 epoch 계약** — 새 판본은 기존 `CE_RUN`의
   `artifacts/epochs/<cex-id>/pivots/<route-id>/contract.md`와 새 동결 fixture로
   세운다. 새 top-level run을 만들지 않는다. 구 fixture 위에서 식만 바꿔
   통과를 재측정하는 것은 개정이 아니라 재조정이다.
3. **관측 근거 명기** — 어떤 관측 기준선(출처·판·오차 포함)이 개정을
   강제했는지 계약에 적는다. sourcer 검증을 거치지 않은 관측값은 근거가
   될 수 없다.
4. **falsifier 선동결** — 새 식이 재현해야 할 관측 무차원 비율들을 결과
   확인 전에 동결하고, 자유 파라미터 수가 재현 비율 수보다 **적어야**
   한다. 비율별 개별 재조정(per-observable retune)은 금지. 전 비율
   동시 재현 실패는 그 족의 STOP이며 산출이다.
5. **지위 규율** — 새 식의 지위는 통과 후에도 [경험식] 또는 [예측]이며,
   ce-closure-gate 없이 유도됨·닫힘을 쓰지 않는다.

T 확정 뒤 바로 주장 범위를 줄이거나 BLOCKED로 닫지 않는다. 먼저 실패한 부모
주장과 witness를 `COUNTEREXAMPLE_LOCKED`로 고정하고, 서로 다른 상태·상호작용·
측정모형·개입항을 바꾸는 기전 route를 최소 3개 만든다. 각 route는 새 식,
조정 자유도, 판별 예측, adverse control, 봉인된 split, kill condition을 가진다.
축소된 참 명제는 보존 기록이지 식 개정의 성공 판정이 아니다.
