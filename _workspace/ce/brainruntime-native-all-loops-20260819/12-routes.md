# Alternative implementation routes

Status: COMPLETE

## Route A -- causal native eligibility (selected)

Add an opt-in causal eligibility orientation to the existing STDP tracker and a separate native
replay controller around `BrainRuntime`. Replay trajectories are generated by runtime steps,
scalar gates apply eligibility to `BrainRuntime.weight`, sparse state is rebuilt, both external
stores are detached, and recall uses a fixed decoder after cue plus free rollout.

Advantages: it exercises the repository's actual recurrent plasticity path and exposes genuine
failure if local replay credit is insufficient. Risks: structural projection can dominate small
updates, and the old absolute-spike eligibility may still fail to bind dense symbolic codes.

## Route B -- supervised low-rank recurrent write (fallback only)

Fit a bounded low-rank delta from replayed native cue and target states, install it into
`BrainRuntime.weight`, and rebuild sparse state. Recall remains native, but consolidation is a
supervised outer-product writer rather than the repository STDP rule. If Route A fails, Route B
may be run and reported separately; it cannot retroactively turn Route A into GO.

## Route C -- shadow consolidation (rejected for this contract)

Keep the existing NumPy association/attractor matrices or inject their output during recall.
This may remain a useful control, but it violates the native recurrent-weight and independent
readout criteria.

## Decision

Implement Route A first. Route B is authorized only as a separately labeled mechanism/control
after Route A's result is frozen. Route C cannot satisfy the research question.
