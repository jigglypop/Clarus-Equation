# 시작 조건

감사(20-audit.md, Gate: PASS)와 검증 결과가 완료돼야 한다. `status <run-dir>`로 선행 단계를 확인한다. 새 증거가 필요하면 작성하지 말고 담당 역할로 돌려보낸다. 리라이트 중 어떤 판정도 강화하지 않는다 — 레인이 경험식이라 한 것을 산출로, BLOCKED를 "사실상 해결"로 바꿔 쓰지 않는다.

# 주장 분류

- 모든 활성 주장을 정의, 정리, 공리, 산출, 경험식, 미완성, 예측으로 분류하고 본문에 표시한다.
- 정리는 명시한 정의역과 공리에서 완전히 증명된 경우에만 사용한다.
- 분기, 정규화, 외부 입력, 물리 사상과 scale은 공리다.
- ε_*, ε_obs, ε_field, ε_mass, ε²와 ξ, ξ_flow를 섞지 않는다.
- 완전한 반례가 무너뜨린 부모 주장과 취소선 역사는 활성 문서에서 제거한다.
- ce-closure-gate 기록이 없는 주장에 "유도됨", "제1원리", "닫힘"을 쓰지 않는다.

# 구성

다음 순서를 기본으로 한다. 절이 비면 이유를 한 줄로 남기고 절을 유지한다.

1. **초록**: 6문장 이내 — 배경, 문제, 방법, 핵심 결과(수치 포함), 형식 지위, 한계.
2. **서론**: 문제 설정과 기존 정본과의 관계. 결과 예고는 지위 태그와 함께 한 문장.
3. **정의·표기**: 사용하는 모든 기호를 첫 등장 전에 정의. 정의역·단위·무차원 여부 명시.
4. **공리**: 번호를 붙여 나열하고 각각에 `수학 공리|모델 선택|물리 사상|외부 입력` 하위 분류를 단다.
5. **정리와 증명**: 정리 → 증명(□로 종결) → 따름정리 순. 증명이 길면 보조정리로 분해한다.
6. **산출**: 사용한 정리·공리 번호와 입력을 명시하고 추가 선택이 없음을 확인한다.
7. **관측 비교**: 모델 값, 기준값, 불확도, 잔차, 데이터셋·릴리스·스냅샷 날짜만 중립 서술. 형식적 진리 판정 금지.
8. **미완성 과제와 한계**: 미해결 P0/P1, 열린 가설, 적용 범위의 경계.
9. **재현성**: 실행 명령, 시드, 데이터 스냅샷, run 디렉토리 경로.
10. **참조**: 식별자(arXiv ID, DOI, PDG ID, 릴리스명)와 접근 날짜. 2차 인용 금지.

# 문장 규칙

- 본문은 완결된 문단 산문으로 쓴다. 불릿·표는 열거와 비교에만 쓰고, 논증·유도·해석은 반드시 이어지는 문장으로 서술한다. 파편 문장과 개조식 나열로 본문을 대체하지 않는다.
- 각 절은 그 절이 무엇을 보이는지 말하는 도입 문장으로 시작하고, 수식·표 앞뒤를 산문으로 연결한다. 수식만 던져 놓고 다음 절로 넘어가지 않는다.
- 최종 보고서는 자기완결적으로 쓴다. 독자가 레인 파일을 열지 않고도 논증을 따라올 수 있도록 핵심 유도와 근거를 본문에 서술하고, 경로 인용은 상세 재현용 보조로만 쓴다. 분량 규율은 중간 레인 산출물에 적용되는 것이며, 최종 보고서·논문은 완결성과 가독성이 우선한다.
- 평서문 현재형, 능동태를 기본으로 한다. "~로 보인다", "~라고 할 수 있다" 같은 무근거 완곡을 쓰지 않는다.
- 한 문장에 한 주장. 접속 부사(그러나, 따라서)는 논리 관계가 실제로 있을 때만 쓴다.
- 헤지는 지위에 정확히 맞춘다: 정리·산출은 "성립한다/따라온다", 경험식은 "관측과 부합한다", 가설은 "~일 수 있다(검증 조건 병기)".
- 용어는 문서 전체에서 하나로 통일하고, 번역이 불안정한 술어는 첫 등장에서 원어를 괄호 병기한다.
- 독자가 재구성할 수 없는 대명사 지시("이것", "위 결과")를 피하고 번호로 지시한다(정리 3, 식 (7)).

# 금지 표현

돌파구·혁신적·세계 최초·놀라운 등 과장어. 자명하다·쉽게 알 수 있다 등 증명 회피어. 매우·극적으로·완벽히 등 정도 부사. 검증 기록 없는 유도됨·제1원리·닫힘·해결됨. 기계 검사 상태 문자열(PASS 등)을 이론 지위처럼 본문에 복사하는 것.

# 수식·수치 표기

- 수식 구분자는 마크다운 렌더러가 실제로 처리하는 것만 쓴다: 블록 수식은 별도 줄의 `$$ ... $$`, 인라인은 `$...$`. `\[ \]`와 `\( \)`는 GitHub·VSCode 프리뷰에서 렌더링되지 않으므로 금지한다.
- 수학 기호는 수식 모드로 쓴다(`$V_b$`, `$\rho(M)<1$`). 백틱 코드스팬은 코드 식별자·파일명·CLI에만 쓰고, 같은 기호를 코드스팬과 수식 모드로 혼용하지 않는다.
- 표 셀과 제목 안에는 블록 수식을 넣지 않는다. 표에는 인라인 수식이나 기호명만 쓴다.
- 재인용되는 수식에는 번호를 붙이고 번호로만 재지시한다. 각 수식 뒤에 의미를 한 줄로 설명한다.
- 유도의 각 단계에 사용한 정리·공리 번호를 붙인다. 단계 생략은 보조정리로만 한다.
- 수치는 불확도에 맞는 유효숫자로 쓰고 오차와 기준선(예: Planck 2018, PDG 2024)을 병기한다.
- 차원 있는 양은 단위를, 코어에 들어가는 인자는 무차원임을 명시한다. 의심스러우면 $ce-dimensionless로 검사한다.
- 표는 비교 대상이 3개 이상일 때만 쓰고, 표의 각 열에 단위·출처를 적는다.

# 출력

40-final-report.md 또는 지정 원고에 Status: COMPLETE/BLOCKED와 최종 판정, 근거, 한계, 미해결 P0/P1, 재현 경로를 남긴다. 문서 수정은 검증자가 승인한 범위에 한정하고, 정본 문서 반영은 $ce-doc-write 규약을 따른다.
