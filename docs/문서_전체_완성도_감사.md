## 2. 전체 판정

현재 `docs/`는 **내부 연구 노트와 이론 정본으로는 80점대**, **외부 제출용 논문 묶음으로는 60점대 후반**이다.

가장 큰 장점은 다음이다.

- `README.md`가 오일러 항등식의 지위를 "직접 증명식"이 아니라 "최소 생성 문법"으로 낮춰 과잉 주장을 잘 막는다.
- `상수.md`가 `Exact / Selection / Bridge / Phenomenology / Open / Open test` 등급을 도입해 수치 결과의 주장 강도를 분리한다.
- `경로적분.md`는 계산 체인의 중심 문서로 충분한 밀도와 교차 검증 항목을 가진다.
- `6_뇌/`와 `7_AGI/`는 구조 유비를 실험 게이트와 런타임 사양으로 낮춰 읽으려는 장치가 있다.
- `4_공학적_활용/09_무차원_잔차장_환각억제.md`와 `08_기상_그래프잔차_연구.md`는 응용 문서 중 논문형으로 승격하기 쉬운 편이다.

가장 큰 약점은 다음이다.

- 많은 하위 문서가 초록, 기여, 반증 조건, 한계, 재현성 블록 없이 바로 수식으로 들어간다.
- 일부 문서는 `Exact`, `Bridge`, `Phenomenology`가 문장 안에서 다시 섞이며, 독자가 어느 세기의 주장인지 즉시 알기 어렵다.
- `README.md`의 폴더 구조 표가 `7_AGI/`, `8_리만/`을 별도로 설명하지 않아 현재 실제 규모와 맞지 않는다.
- 코드 경로가 레거시와 현재 checkout 사이에서 흔들린다. 실제 파일이 없는 `examples/...`, `quant/...` 참조는 "현재 구현"이 아니라 "과거 패턴 또는 추가 예정"으로 표시해야 한다.
- 외부 논문 형식의 참고문헌, 데이터 provenance, 재현 스크립트, 결과 JSON 규약이 폴더 전체에 균일하지 않다.

## 4. 우선순위

### P0: 정본 지도 갱신

`README.md`를 현재 실제 구조에 맞춰 갱신해야 한다.

- `7_AGI/`와 `8_리만/`을 폴더 구조 표에 추가한다.
- `4_공학적_활용/` 설명에 07-09 문서를 포함한다.
- "실행 예제는 `reality_stone/examples/unified_clarus_demo.py`로 통합" 원칙과 하위 문서의 레거시 코드 참조가 충돌하지 않도록 읽기 규칙을 추가한다.

### P1: 모든 문서 상단에 status box 추가

각 문서 첫 20줄 안에 아래 블록을 넣으면 전체 완성도가 크게 오른다.

```text
상태: Exact / Selection / Bridge / Phenomenology / Open / Spec
역할: 정본 / 강의 / 응용 / 실험 프로토콜 / 참고
입력: 이 문서가 전제하는 값과 문서
출력: 이 문서가 새로 주장하는 값과 식
검증: 관측, 코드, 실험, 반증 조건
```

우선 적용 대상:

1. `2_경로적분과_응용/*.md`
2. `4_공학적_활용/*.md`
3. `5_유도/*.md`
4. `7_AGI/*.md`

### P2: H1 없는 문서 정리

H1 없이 `##`로 시작하는 파일은 독립 문서로 열면 제목이 사라진다. 특히 다음 그룹은 정리 가치가 높다.

- `3_상수/7_우주론.md`
- `3_상수/9_우주론_수식_의미와_후보.md`
- `5_유도/*.md`
- `6_뇌/05_실험근거/*.md`
- `6_뇌/09_생명에서지능까지/*.md`

단, 하위 장으로 의도된 파일이라면 `# 상위장 - 하위장` H1을 붙이고 기존 번호는 `##` 이하로 내리는 방식이 가장 안전하다.

### P3: 반증 조건 표준화

반증 조건이 있는 문서는 25개뿐이다. 과학/공학 주장 문서에는 최소한 아래 표를 넣어야 한다.

| 반증 조건 | 해당 주장 | 판정 기준 | 다음 조치 |
|---|---|---|---|
| 관측값과 3σ 이상 괴리 | Bridge 식 | reject 또는 Open 하향 | 대체 브리지 검토 |
| shuffled/flat baseline보다 낮지 않음 | 응용 gate | Phenomenology 하향 | graph 항 제거 또는 진단 도구로 제한 |
| holdout에서 무너짐 | 일반화 주장 | reject | train-only 보정으로 재분류 |

### P4: 코드와 문서 경로 일치

현재 checkout에서는 과거 `examples/...`, `quant/...`, `clarus/...` 경로가 삭제되거나 `reality_stone/...`로 이동한 흔적이 많다. 문서가 실행 파일을 언급할 때는 세 등급으로 나눠야 한다.

| 표기 | 의미 |
|---|---|
| 현재 구현 | 현재 checkout에 실제 파일 존재 |
| 과거 패턴 | 과거 구현 또는 문맥 추출에는 있으나 현재 파일 없음 |
| 추가 예정 | 설계상 필요하지만 아직 없음 |

`08_기상_그래프잔차_연구.md`는 이 원칙에 맞춰 "추가할 실행 파일"로 낮춰 쓰는 편이 맞다.

### P5: 외부 제출용 논문 후보 분리

현재 폴더 전체를 하나의 논문으로 내기보다는, 제출 후보를 분리하는 편이 낫다.

| 후보 | 현재 준비도 | 이유 |
|---|---:|---|
| CE 상수/우주론 scorecard | 높음 | `경로적분.md`, `상수.md`, `3_상수/`가 이미 정본화됨 |
| H0 source-role readout | 중간-높음 | audit/paper draft 구조가 있음 |
| 무차원 hallucination gate | 중간 | 수식 명료, 구현/벤치만 붙이면 됨 |
| 기상 graph residual gate | 중간 | 예비 수치와 프로토콜 있음, 재현 패키지 필요 |
| 뇌-AGI runtime spec | 중간 | 문서량은 많지만 주장 층위 분리가 더 필요 |
| Riemann/MRA | 중간 | `mra_paper.md`는 좋고 spec 문서는 검증 블록 필요 |
| 핵융합/초전도/진공에너지 공학 | 낮음-중간 | 아이디어는 많지만 실험 현실성, 비용, 반증 조건 보강 필요 |

3. H1 없는 22개 문서에 H1 추가.
4. `2_경로적분과_응용/` 14개 문서에 status box와 반증 조건 추가.
5. `4_공학적_활용/` 01-07 문서의 공학 주장 강도를 `Application Bridge` 또는 `Speculative Engineering`으로 명시.

8. 논문 후보 3개만 먼저 골라 재현성 패키지까지 닫기: `상수/우주론`, `hallucination gate`, `기상 graph residual`.

## 6. 결론

`docs/`는 이미 단순 아이디어 모음은 아니다. 핵심 정본, 수치 집계, 응용 문서, 뇌/AGI 사양까지 갖춘 큰 연구 노트다. 다만 완성도를 가르는 병목은 "내용 부족"이 아니라 **주장 강도와 재현성의 균일성 부족**이다.

현재 가장 좋은 전략은 전체를 한 번에 논문으로 만들기보다, 문서군을 다음 세 층으로 고정하는 것이다.

1. `경로적분.md` + `상수.md`: CE core scorecard.
2. `2_경로적분과_응용/`, `3_상수/`: core의 하위 유도와 관측량 세부 근거.
3. `4_공학적_활용/`, `5_유도/`, `6_뇌/`, `7_AGI/`, `8_리만/`: Application Bridge와 실험 후보.

이렇게 나누면 강한 주장은 더 강해지고, 약한 주장은 약하다고 말할 수 있어서 전체 신뢰도가 올라간다.
