# CE 문서 작성 규약

CE 문서는 이론물리 모델의 **형식적 출처**와 **관측 비교**를 분리한다. 관측값과 잘 맞는다는 사실은 증명이 아니며, 명시한 공리로부터 완전하게 증명된 수학 명제는 관측 비교가 없어도 정리이다.

## 라우팅과 역할 분리

이 스킬은 공통 지위 규약과 라우팅만 맡는다. 실제 작성 역할은 문서 유형에 따라 분리한다.

- 주장·상수·판본·진리값 원장은 `$ce-ledger-write`와 `ce-ledger-writer`가 소유한다.
- 강의·유도·독자 가이드·논문 원고는 `$ce-paper-write`와 `ce-paper-writer`가 소유한다.
- 한 요청에 두 유형이 섞이면 원장 작성자가 먼저 지위와 의존 관계를 안정화하고 편집을 멈춘다. 논문 작성자는 그 원장을 읽기 전용 입력으로 받아 집필한다.
- 한 작성자가 원장과 논문을 오가며 동시에 수정하지 않는다. 논문에서 원장 충돌을 발견하면 원장을 직접 고치지 말고 충돌 위치와 필요한 보조정리를 보고한다.

문서 유형이 불분명하면 표·판정·판본 관리가 주목적인지, 독자가 논증을 따라가도록 설명하는 일이 주목적인지로 결정한다. 두 목적을 한 파일에 섞지 않는다.

## 형식적 출처

모든 비자명한 활성 주장은 다음 중 하나로 표시한다.

- `[정의]`: 기호·대상·연산·정의역을 선언한다. 정의는 참·거짓을 판정하는 명제가 아니다.
- `[정리]`: 정의역과 전제를 명시했고, 그 전제에서 결론까지 빠짐없는 증명이 있다.
- `[공리]`: 모델이 채택한 독립 전제·선택·물리 사상이다. 공리를 산출이나 제1원리 유도로 부르지 않는다.
- `[산출]`: 명시한 정리와 공리에서 추가 선택 없이 따라오는 식·수치·구조이다. 사용한 입력을 함께 적는다.
- `[경험식]`: 관측 또는 수치 패턴을 바탕으로 제안한 관계식이다. 정리나 산출로 승격하지 않는다.
- `[미완성]`: 정의, 작용, 사상, 증명 또는 동역학 중 필요한 부분이 비어 있다.
- `[예측]`: 입력·범위·비교 절차를 사전에 고정한 관측량이다. 이 표시는 형식적 출처를 대신하지 않으므로 바로 앞에 의존 공리와 산출을 적는다.

`[공리]`에는 필요하면 `수학 공리`, `모델 선택`, `물리 사상`, `외부 입력`이라는 짧은 하위 설명을 붙인다. 같은 기호가 다른 층을 가리키면 기호를 분리한다. 정본에서는 `q_ext`를 소멸확률, `s_branch=1-q_ext`를 생존확률로 쓴다.

## 완전한 반례 처리

부모 명제가 자신의 명시된 정의역 안에서 완전한 반례, no-go 정리 또는 재현 가능한 계산으로 무너지면 다음을 적용한다.

1. 그 부모 명제, 식, 결과 행, 요약 표와 이를 해명하는 취소선·역사 설명을 활성 Markdown에서 삭제한다.
2. 반례를 피하도록 정확히 좁힌 참 명제가 있으면 별개의 `[정리]` 또는 `[산출]`로 다시 쓴다.
3. 같은 오류의 재도입을 막는 증인은 테스트 코드에만 남긴다. 사용자 문서에는 실패한 부모 식을 다시 전시하지 않는다.
4. 전제 누락이나 계산 미완료처럼 반례가 완전하지 않으면 삭제하지 않고 `[미완성]`으로 둔다.

수학적 no-go 자체가 완전한 증명인 경우에는 그 no-go를 `[정리]`로 보존한다. 삭제 대상은 no-go가 무너뜨린 부모 주장이다.

## 관측 비교

관측 비교 표에는 모델 값, 기준값, 불확도, 잔차, 데이터셋과 스냅샷 날짜만 중립적으로 기록한다. 이 표에 형식적 진리 판정을 쓰지 않는다.

- 데이터가 특정 물리 해석을 완전히 배제하면 그 해석을 활성 본문에서 제거한다.
- 같은 수학 구조가 다른 해석 아래 여전히 성립하면 그 구조는 남긴다.
- 외부 입력은 반드시 `[공리: 외부 입력]`으로 기록한다. 특히 `alpha_s`를 무입력 산출로 세지 않는다.
- 사후 탐색·보정·scale fit은 `[경험식]`이며 사전 예측으로 바꾸어 쓰지 않는다.

## 문서 유형: 원장과 논문형

CE 문서는 두 유형으로 나뉘며, 유형을 혼동하는 것이 가장 흔한 문체 실패다.

- **원장(ledger)**: 주장·지위·수치를 표와 항목으로 관리하는 감사 문서 (예: 진리값 감사, 우주론 원장). 태그 나열이 기본이다.
- **논문형**: 강의(`1_강의`), 유도(`5_유도`), 논문 원고, 독자 가이드. **서사가 기본이고 태그는 서사에 붙는다.** 태그 블록을 원장처럼 나열하기만 한 강의·유도 문서는 미완성 원고로 취급하고 다시 쓴다.

논문형 문서는 다음을 지킨다.

- 첫 두 문단만 읽고 독자가 세 가지를 알 수 있어야 한다: 이 문서가 무엇을 보이는지, 왜 그것이 필요한지, 어떤 순서로 진행되는지. 태그 표나 기호 정의로 문서를 시작하지 않는다.
- 전제 독자와 필요한 배경지식을 서두에 한 문장으로 명시한다.
- 두 태그 블록을 연결 산문 없이 붙이지 않는다. 각 블록 앞에는 "앞에서 무엇을 얻었고, 그래서 지금 왜 이것을 하는지"를 말하는 문장이 있어야 한다.
- 핵심 개념마다 구체 예시 또는 비유를 최소 하나 두고, 비유가 깨지는 지점을 함께 명시한다.
- 다른 문서를 먼저 읽어야만 이해되는 서술은 해당 문서 링크와 한 줄 요약을 함께 둔다.

## 처음 읽는 독자 게이트

논문형 문서는 탈고 후 "이 주제를 처음 보는 독자"로 처음부터 다시 읽으며 다음을 검사한다. 하나라도 어기면 수정 전에는 완성으로 보고하지 않는다.

1. 모든 기호는 첫 등장에서 말로 된 이름과 한 줄 의미를 함께 받는가. 기호를 먼저 쓰고 설명을 뒤로 미루지 않는다.
2. 정의·도입한 대상은 반드시 같은 문서 뒤에서 사용되는가. 사용하지 않는 기호·정의는 삭제하거나 사용하는 자리로 옮긴다.
3. 각 절의 첫 문장이 이전 절과의 논리적 연결을 말하는가.
4. 아직 정의되지 않은 개념에 의존하는 문장이 없는가. 발견하면 정의를 앞으로 옮기거나 문장을 뒤로 보낸다.
5. 독자가 종이와 펜만으로 각 유도를 재현할 수 있는가.

## 문체와 수식 표기

- 본문은 완결된 문단 산문으로 쓴다. 불릿·표는 열거와 비교에만 쓰고, 논증과 유도는 이어지는 문장으로 서술한다. 각 절은 무엇을 보이는지 말하는 도입 문장으로 시작한다.
- 수식 구분자는 블록 `$$ ... $$`(별도 줄), 인라인 `$...$`만 쓴다. `\[ \]`와 `\( \)`는 GitHub·VSCode 프리뷰에서 렌더링되지 않으므로 금지한다.
- 수학 기호는 수식 모드(`$V_b$`)로 쓴다. 백틱 코드스팬은 코드 식별자·파일명·CLI에만 쓴다. 표 셀에는 블록 수식을 넣지 않는다.
- 재인용되는 수식에는 번호를 붙이고, 각 수식 뒤에 의미를 한 줄로 설명한다.

## 논문 문장 규약 (한글 논문체)

- 핵심 기여를 한두 문장으로 먼저 확정하고 모든 내용을 거기에 복무시킨다. 핵심을 흐리는 내용은 제거한다.
- 독자는 "이 주제를 1년 전에 처음 배우던 시절의 저자 자신"으로 설정하고, 그 독자가 헷갈릴 지점을 본문에서 미리 해소한다.
- 서론에서 가능한 한 빨리 핵심 결과를 제시하고, 표준적인 정의는 뒤로 미룬다. 정의는 그것을 쓰는 정리보다 앞에 둔다.
- 정리(핵심 결과)·보조정리(도구)·따름정리(파생 결과)를 구분해 라벨을 붙인다. 본문에 증명을 서술할 때는 "증명."으로 시작해 □로 끝낸다. 정본 문서의 증명은 `핵심_정리_증명.md` 원장 링크를 우선하고, 원고에서만 본문 증명을 쓴다.
- 유도 전개는 한 줄에 한 단계씩 적고, 각 단계마다 적용한 정의·가정·법칙을 말로 밝힌다. "정리하면", "쉽게 알 수 있듯이"로 여러 단계를 건너뛰지 않는다. 독자가 종이와 펜만으로 모든 수식을 재현할 수 있도록 조건·근사·경계조건을 빠뜨리지 않는다.
- 논증에 쓰는 모든 가정은 논증을 시작하기 전에 명시하고, 결론에서 가정을 재사용하는 순환 논증을 하지 않는다. 각 단계가 앞 단계에서만 따라 나오는지 검사한다.
- 지위 태그를 쓰지 않는 산문 맥락에서 저자의 독자적 제안은 "본 논문에서 제안하는"으로 표시하고, 기존 결과에는 출처를 단다. 독자적 제안을 기존에 확립된 것처럼 서술하지 않는다.
- 직관적 논의는 "직관적으로는" 또는 "참고(Remark)" 표시와 함께만 쓰고, 엄밀한 증명과 섞지 않는다.
- 문장을 기호나 숫자로 시작하지 않는다. 논리 기호(∀, ∃, ⇒)를 산문에 쓰지 않고 말로 푼다. 말로 충분한 것을 기호로 쓰지 않으며, 한 번 정한 용어와 표기는 끝까지 일관되게 쓴다.
- 문장 기준은 길이가 아니라 논리 흐름이다. 한 문장에 논리 단계를 두 개 이상 넣지 않고, 한 문단에는 하나의 아이디어만 담는다. 별행 수식도 문장의 일부로서 구두점을 지킨다.
- 필요한 용어는 "한글 용어(영문 원어)" 형태로 처음 한 번만 병기한다.

## 번역투 방지

다음은 한국어 논문에서 가장 흔한 번역투다. 반드시 고쳐 쓴다.

- 이중 피동 금지: "~되어진다", "~라고 보여진다" → "~된다", "~라고 본다".
- 행위자가 분명하면 능동으로: "실험이 수행되었다" → "실험을 수행했다".
- "~에 있어서" 금지 → "~에서", "~할 때".
- "~에 대하여/대한" 남용 금지: "수렴성에 대한 증명" → "수렴성 증명".
- "~를 가진다" 직역 금지: "중요한 의미를 가진다" → "의미가 크다", "해를 가진다" → "해가 있다/존재한다".
- "~로부터" 남용 금지: "식 (3)으로부터" → "식 (3)에서".
- "~의" 연쇄 금지: "문제의 해결의 방법" → "문제 해결 방법".
- 무생물 주어의 타동사 구문 지양: "이 결과는 우리에게 ~을 보여준다" → "이 결과에서 ~을 알 수 있다".
- "가장 ~한 것 중 하나" 금지 → "대표적인 ~", "~한 예다".

## 작업 방식

- 초안 요청에는 정의 → 보조정리 → 정리의 의존 관계를 확정한 개요를 먼저 제시하고 확인받은 뒤에 본문을 쓴다.
- 저자의 수학적 내용을 임의로 바꾸지 않는다. 논증에 공백이 의심되면 그럴듯한 문장으로 메우지 말고, 공백이 있다고 보고하거나 질문한다.

## 승격 정책

정본 문서와 artifacts는 갱신하는 것이지 증식시키는 것이 아니다.

- 기존 주제의 후속 결과는 해당 정본 문서를 제자리 갱신한다. 새 번호 문서는 감사가 별개 정본 주제로 인정한 경우에만 만든다.
- v2, v3, `_new`, `_final` 같은 파생 사본을 정본 디렉토리에 만들지 않는다. 판본 역사는 run 디렉토리와 git이 보관한다.
- artifacts 승격은 최종 승인분만 한다. 사전등록·중간 진단 산출물은 run의 artifacts/에 남긴다. 같은 기능의 관련 JSON은 기능별 하위 디렉토리로 묶는다.
- 문서를 갱신하면 무너진 옛 서술을 같은 커밋에서 제거한다.

## 작성 순서

1. `docs/axium.md`의 정의와 기호를 확인한다.
2. 원장형 문서의 각 절은 정의역과 정의 → 공리 → 정리 → 산출 → 관측 비교 → 미완성 과제 순으로 배열한다. 논문형 문서는 이 배열보다 "문서 유형: 원장과 논문형"의 서사 규칙을 우선하고, 태그 순서는 절 안의 논증 흐름을 따른다.
3. 지수·로그·확률 코어는 `ce-dimensionless`로 검사한다.
4. 수학적 완결성은 `ce-closure-gate`, 수치·회귀 무결성은 `ce-validate`로 검사한다.
5. 문서에 기계 검사의 상태 문자열을 이론 지위처럼 복사하지 않는다.

## 금지

- 공리를 유도 또는 발견이라고 부르기
- 관측 근접을 수학적 증명으로 부르기
- 완전한 반례가 있는 부모 주장을 경고표·취소선·역사 부록에 보존하기
- 정의역과 전제 없이 보편 명제를 쓰기
- 정본과 다른 수치를 근거 없이 쓰기
